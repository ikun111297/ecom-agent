# 电商智能客服 Agent

基于大模型（DeepSeek）的电商售前导购 + 售后自动化客服系统，支持 RAG 知识库检索与订单工具调用。

## 功能

- **售前导购**：根据用户需求推荐商品、回答参数、引导下单
- **售后自动化**：查询订单状态与物流、退换货规则问答
- **RAG 检索增强**：知识库切块 + 查询改写 + BM25 检索 + 相似度阈值过滤
- **工具调用**：模型自主调用 `query_order` 查询真实订单数据
- **多渠道**：命令行 / 飞书机器人，业务逻辑与渠道完全解耦
- **自动评测**：LLM-as-judge 评测框架

## 架构

```
knowledge/  data/                       数据层：知识库文档、订单数据
      |
core/
  knowledge.py    知识库加载与清洗
  retriever.py    切块 + 查询改写 + BM25 检索
  tools.py        订单查询工具
  llm.py          大模型调用封装
  prompts.py      售前 / 售后 提示词
  sales.py        售前逻辑
  aftersales.py   售后逻辑（含工具调用循环）
      |
channels/
  cli.py          命令行渠道
  feishu.py       飞书机器人渠道（长连接）
```

新增渠道只需实现 `new_history()` 与 `ask(question, history)` 两个接口，`core/` 无需改动。

## 技术要点

### RAG 流程

1. 知识库按空行切块，每块一个独立知识点
2. 用大模型把口语问题改写成检索关键词（解决"多少钱"匹配不上"价格"的词汇鸿沟）
3. BM25 打分，检索 top-3；改写词与原词共同参与打分，改写跑偏时原词兜底
4. 相似度低于阈值时返回"未检索到"，而不是硬塞无关内容

### 防幻觉设计（三层）

| 层级 | 手段 |
| --- | --- |
| 检索层 | 相似度阈值过滤，无相关内容时明确告知模型 |
| 工具层 | 订单数据只能由 `query_order` 提供，模型无法编造 |
| 提示词层 | 禁止"我帮您确认一下"等无法兑现的话术 |

### 分层架构

渠道层只负责收发消息，业务逻辑集中在 `core/`。接入飞书时 `core/` 零改动。

## 评测结果

16 条测试用例（14 条正向 + 2 条幻觉诱导）：

| 指标 | 结果 |
| --- | --- |
| 正向准确率 | 14/14 = 100% |
| 幻觉拦截率 | 2/2 = 100% |

评测采用 LLM-as-judge：由模型判断回答是否准确表达期望语义，避免关键词匹配的脆弱性（实测中模型答"可以用"而词表写"可用"会误判）。

## 快速开始

```bash
pip install openai python-dotenv jieba rank_bm25 lark-oapi
```

创建 `.env`：

```
DEEPSEEK_API_KEY=你的密钥
FEISHU_APP_ID=你的应用ID
FEISHU_APP_SECRET=你的应用密钥
```

运行命令行版本：

```bash
python -m channels.cli
```

运行飞书机器人：

```bash
python -m channels.feishu
```

运行评测：

```bash
python -m eval.run_eval
```

## 知识库格式

`knowledge/` 下的 Markdown 文件会被自动加载，新增或替换文件**无需修改代码**。

商品：

```markdown
## 商品名称
- 价格：99元
- 卖点：补水保湿、敏感肌可用
- 规格：25ml x 10片
- 库存：有货
```

问答（FAQ / 售后规则通用）：

```markdown
Q：敏感肌能用吗？
A：XX面膜敏感肌可用，建议先耳后测试。
```
